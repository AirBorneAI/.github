# Contributing to AirBorne

Thank you for your interest in contributing to **AirBorne** open-source engineering initiatives!

## Development Workflow

1. **Fork & Branch**: Create a feature branch with a descriptive name (`feat/module-name` or `fix/issue-description`).
2. **Coding Standards**:
   - Write clean, type-annotated code (Python / TypeScript / Rust / Go).
   - Maintain comprehensive unit and integration tests.
   - Adhere to conventional commit standards (`feat: ...`, `fix: ...`, `docs: ...`, `refactor: ...`).
3. **Testing**: Ensure all automated test suites and linting passes before opening a Pull Request.
4. **Pull Requests**:
   - Link any associated issues.
   - Provide a clear explanation of the architectural change and verification steps.

## Code of Conduct

All contributors are expected to uphold our [Code of Conduct](./CODE_OF_CONDUCT.md).
